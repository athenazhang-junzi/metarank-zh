# 生产环境运行建议

## 持久化

上游建议生产环境使用独立 Redis 保存状态：

- Redis 生命周期与 Metarank 服务实例分离；
- Metarank 重新部署时不会丢失状态；
- Redis 本身仍需配置磁盘持久化、备份和恢复演练。

Metarank 在 Redis 中保存处理后的状态，仍应在独立事件系统中长期保存原始事件，以便重新导入、审计和故障恢复。

## API 服务

`standalone` 适合开发，但不应作为生产部署模式：

- 无法通过多个共享同一状态的 Standalone 进程安全扩展完整流程；
- 重训练与推理处于同一进程；
- 训练可能造成内存压力和延迟波动。

生产环境应使用 `serve`：

- 可以按负载部署多个服务实例；
- 支持滚动或优雅重启；
- 推理资源通常低于训练资源；
- 多实例前需要外部负载均衡器。

Metarank 本身不提供完整的集群编排、外部认证和业务级限流，应由部署平台补齐。

## 重训练

`train` 是长时间、高内存任务，资源消耗取决于点击链规模和模型配置。应作为按需或定时独立任务运行，例如每周或每月，而不是常驻在昂贵训练节点上。

训练频率应由数据变化速度、模型衰减、业务周期和验证成本决定；不应机械采用固定周期。

## 最小生产检查清单

- Redis 备份、恢复和容量告警；
- 原始事件独立留存；
- `serve` 多实例与外部负载均衡；
- API 网络访问控制；
- 推理延迟、错误率和特征缺失监控；
- 独立训练资源与模型质量门禁；
- 模型版本、回滚和加载一致性；
- 匿名分析与错误上报设置符合隐私要求。
