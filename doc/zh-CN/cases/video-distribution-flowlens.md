# Metarank × FlowLens：视频内容分发案例

> 本文是中文仓库新增案例，不是 Metarank 官方文档。  
> 案例用于说明产品与系统边界，不代表两个项目已经完成代码集成。

## 问题背景

视频内容分发不仅要预测用户是否点击，还需要同时考虑有效观看、负反馈、内容覆盖、作者重复、标签重复和新内容探索。

在这条链路中，Metarank 和 FlowLens 位于不同层级：

- **Metarank**：接收候选视频，计算特征并返回新的排序；
- **FlowLens**：检查数据可靠性，设计分发策略，并用多目标指标决定继续、重测还是停止；
- **FlowLens LiveLab**：演示分流、触发、污染、事件完整性和决策记录等实验治理流程。

## 能力关系

```text
候选视频召回
    ↓
Metarank：特征计算 → 模型打分 → 返回排序
    ↓
播放器或内容流展示
    ↓
曝光、点击、起播、长播、负反馈
    ↓
FlowLens：数据检查 → 策略评估 → 多目标护栏 → 决策
    ↓
LiveLab：实验健康检查 → 指标解释 → 决策记录
```

## 事件概念映射

| 视频业务概念 | Metarank 中的表达 | FlowLens/LiveLab 中的用途 |
|---|---|---|
| 内容属性 | `item` 事件 | 内容类别、作者、时长等分析维度 |
| 用户或会话属性 | `user`、`session` | 分群、上下文和实验检查 |
| 有序候选列表 | `ranking` 事件 | 曝光和策略版本的基础记录 |
| 点击 | `interaction: click` | 点击率或漏斗节点 |
| 起播 | 可配置的交互类型 | 从点击到消费的中间节点 |
| 有效观看 | 可配置的交互类型 | 更接近内容消费质量的目标 |
| 负反馈 | 可配置的交互类型 | 体验护栏 |

这是一种概念映射，不代表现有两个仓库可以直接交换数据。真正接入时仍需统一事件 ID、时间戳、用户与会话主键、策略版本和去重规则。

## Metarank 补充了 FlowLens 的什么？

- 在线排序服务的接口形式；
- 排序、反馈和训练样本之间的数据关系；
- 实时特征与用户画像更新；
- 多个模型的服务方式；
- Docker、Redis 和流式数据源等工程边界。

## FlowLens 补充了 Metarank 的什么？

- 数据质量和时间泄漏检查；
- 历史曝光日志带来的选择偏差意识；
- 多样性、覆盖、重复和负反馈等多目标护栏；
- 离线结果的置信区间和决策门槛；
- “上线、重测、停止”之间的证据边界。

## 一个可讨论的策略例子

假设目标是减少连续视频流中的作者重复，同时不损害有效观看：

1. 上游召回系统产生候选视频；
2. Metarank 根据相关性、用户兴趣、作者、类别和近期行为产生排序；
3. 业务规则层处理强制去重、审核和供给约束；
4. FlowLens 离线比较有效观看、负反馈、作者重复和内容覆盖；
5. 只有数据质量和护栏满足预设条件时，策略才进入未来线上实验候选；
6. LiveLab 用于演示实验触发、污染、事件完整性和决策记录。

模型分数不能替代业务规则，离线改善也不能直接表述为线上收益。

## 证据边界

- [FlowLens](https://github.com/athenazhang-junzi/FlowLens) 使用公开数据进行离线研究；
- FlowLens LiveLab 使用浏览器本地固定种子模拟数据；
- 当前没有 Metarank 与 FlowLens 的生产级接口；
- 当前没有真实视频平台流量、线上 A/B 结果或业务收益；
- 本案例展示的是系统拆解和策略方法，而不是已经完成的工程集成。
